## 1. 一句话说清 D2 是什么

写一个 FPGA 驱动 `adc_ch0`，让它通过 SPI 向 MCP3208 发出"读取 CH0"的命令并接收 12 位结果；再用一个模拟 ADC 的测试文件，在电脑里把这条链路验证通过。

**今天真正的成果是两个文件，不是"一个测试文件"：**

| 文件 | 角色 | 将来上板吗 |
|---|---|---|
| `src/adc_ch0.v` | **产品**：真正的驱动，会被综合成电路 | ✅ 会，接进 A 的总 top |
| `tb/tb_adc_ch0.v` | **考卷**：只用来考试 | ❌ 永远不上板 |

**在项目数据流中的位置：**

```text
手指按压 → 压力片电阻变化 → 分压电压变化
        → MCP3208 把电压转成 12 位数字
        → 【adc_ch0：用 SPI 把数字读回 FPGA】 ← 这里
        → 力度映射（D4：0～4095 → 0～65535）
        → 队长合成引擎（决定音量和音高）
        → A 的 I2S 输出 → 喇叭
```

> **更准确的比喻**：今天做的不是"给 MCP3208 打了电话"，而是——
> **写好了电话话术（驱动），又找一个人照剧本扮演 MCP3208（测试台），两个人在空房间里对了一遍台词。**
> 全程没插电话线，也没真的拨号。

这样做的价值：**等真芯片到了，只需操心"线接得对不对"，不用再操心"话术对不对"。**

## 2. SPI 是什么：四根线的含义

### 2.1 SPI 的本质

SPI = **S**erial **P**eripheral **I**nterface（串行外设接口），Motorola 发明。

两个特点决定了它的一切行为：

1. **串行（Serial）**：不能一次传一堆，只能**一位一位**地传。
2. **同步（Synchronous）**：靠一根时钟线对齐节奏，双方约定"在这个跳变时刻看线"。

所以 SPI 最少需要 **3 根线（时钟 + 两根数据）**，加上片选变成 **4 根线**。

### 2.2 四个标准信号名

都是从**主机（FPGA）视角**命名的：

| 缩写 | 全称 | 字面意思 | 对 FPGA 的方向 | 谁在发 |
|---|---|---|---|---|
| **CS** | **C**hip **S**elect | 芯片选择（片选） | 输出 → ADC | FPGA |
| **SCLK** | **S**erial **CLK** | 串行时钟 | 输出 → ADC | FPGA |
| **MOSI** | **M**aster **O**ut **S**lave **I**n | 主机输出、从机输入 | 输出 → ADC | FPGA |
| **MISO** | **M**aster **I**n **S**lave **O**ut | 主机输入、从机输出 | 输入 ← ADC | ADC |

**四根线里，3 根是 FPGA 发出去的，1 根（MISO）是 ADC 回给 FPGA 的。**

### 2.3 ⚠️ 最大的坑：同一根线，两头名字不同

去查 MCP3208 手册，你会看到它不叫 MOSI/MISO，而叫 **DIN / DOUT**。名字全对不上，很容易接错。

理由是：**同一根线，站在两头看方向是相反的。

| 主机（FPGA）视角 | 从机（芯片）视角 | 物理上是 |
|---|---|---|
| MOSI（主机输出） | DIN（数据输入） | **同一根线** |
| MISO（主机输入） | DOUT（数据输出） | **同一根线** |

**接线口诀：名字方向相反的接在一起。**

```text
FPGA.mosi  ──→  MCP3208.DIN    (pin 11)
FPGA.miso  ←──  MCP3208.DOUT   (pin 12)
FPGA.sclk  ──→  MCP3208.CLK    (pin 13)
FPGA.cs_n  ──→  MCP3208.CS/SHDN(pin 10)
```

**接反的后果**：读回来全是 0 或全是 1——相当于把"嘴巴"和"耳朵"接到同一条线上。

### 2.4 逐根线的细节

**CS（片选）—— 芯片的开关**

- **低电平有效**。名字里的 `_n` 就是提醒这个（`cs_n` = chip select, negative/active-low）。
- `cs_n = 0` → "芯片，我要跟你说话了"
- `cs_n = 1` → "芯片，你歇着"

**为什么需要它？** 因为 SPI 没有地址。一根 SCLK 上可以挂多个从机，靠"在特定时刻只拉低某一个的 CS"决定跟谁说话。

MCP3208 手册里这根脚叫 **CS/SHDN**，`SHDN` = Shutdown（关断）。**拉高 CS 不只是"不说话"，还让芯片进入低功耗关断状态。**

**SCLK（串行时钟）—— 节拍器**

没有它双方就不知道什么时候该看线。每一位数据都由它的一次跳变驱动：

```text
       ↓ 下降沿：准备数据        ↑ 上升沿：采样数据
       ┌───────┐               ┌───────┐
SCLK ──┘       └───────────────┘       └──
       <1µs>          <1µs>
       ←────── 2µs 周期 = 500kHz ──────→
```

**"下降沿准备、上升沿采样"就是 SPI Mode 0 的定义。**

**MOSI —— 你说的命令**

在本项目里跑的是 `0x06 0x00 0x00`（24 位 = 3 字节）。

**MISO —— 对方回的话**

这是整条链上**唯一"逆着走"的信号**，也是唯一需要**两级寄存器同步**的：

```verilog
miso_meta <= miso;        // 第一级：先抓住外部信号
miso_sync <= miso_meta;   // 第二级：再进主时钟域
```

原因：MISO 来自 FPGA 时钟域之外的芯片，变化时刻和 FPGA 时钟没有配合，直接使用有亚稳态风险。**仿真不会模拟亚稳态，但这是必要的硬件措施。**

### 2.5 记忆口诀

> **CS 是敲门，SCLK 是节拍，MOSI 是你说的话，MISO 是对方回的话。**

## 3. MCP3208 的具体约定

### 3.1 角色分配

| 项目 | 本项目 |
|---|---|
| 主机（Master/Controller） | FPGA Tang Mega 60K NEO |
| 从机（Slave/Peripheral） | MCP3208（8 通道 12 位 ADC） |
| SPI 模式 | **Mode 0**（SCLK 空闲低，下降沿准备、上升沿采样） |
| SCLK 频率 | **500 kHz**（周期 2 µs） |
| 一次事务长度 | **24 个时钟** |
| 本阶段通道 | 单端 **CH0** |

### 3.2 命令字 `0x06 0x00 0x00` 拆开看

```
二进制：0000 0110  0000 0000  0000 0000
        └┬─┘└┬┘  └────┬────┘└────┬────┘
         │   │        │          │
         │   │        │          └─ 后 12 位：ADC 回数据的时间
         │   │        └─ 中间：占位（Null 位，无意义）
         │   └─ 通道选择：110 = 单端 CH0
         └─ 起始位：第一个 "1" 表示命令开始
```

前 12 位是 FPGA 说的话，后 12 位是 ADC 回话的时间窗口。

### 3.3 通道号怎么变（D3 八路扫描的关键）

通道号位于命令的**第 4～6 位**，每个通道递增 `0x08`：

| 通道 | 命令头 |
|---|---|
| CH0 | `0x06` |
| CH1 | `0x0E` |
| CH2 | `0x16` |
| CH3 | `0x1E` |
| CH4 | `0x26` |
| CH5 | `0x2E` |
| CH6 | `0x36` |
| CH7 | `0x3E` |

### 3.4 分频怎么算

```verilog
localparam integer HALF_CYCLES = 50;   // 50MHz / (2 × 50) = 500kHz
```

**推导过程：**

```text
FPGA 主时钟：50 MHz  →  周期 20 ns
想要 SCLK：  500 kHz →  周期 2 µs = 2000 ns
                       半周期 1 µs = 1000 ns

1000 ns ÷ 20 ns = 50 个主时钟  →  HALF_CYCLES = 50
```

**为什么故意这么慢？** 因为真实芯片有建立/保持时间要求，MCP3208 也支持更快的速度，但 500 kHz 留了充足余量，更稳。以后要提速，`HALF_CYCLES` 从 50 改成 25 就是 1 MHz。

## 4. 驱动文件的四个状态

Verilog 里同时干很多事很容易乱，所以用**状态机**一步一步走：

| 状态 | 白话 | 代码行为 |
|---|---|---|
| `IDLE` | 待机，等你说开始 | 等 `start`；`cs_n` 保持高 |
| `SHIFT` | 真正打电话 | 产生 24 个 SCLK，边发命令边收数据 |
| `HOLD` | 挂电话前多握 1 µs | 最后一个时钟后保持 CS 低 |
| `GAP` | 喘口气，再公布结果 | 保证 CS 高约 1 µs，然后发布 `data`、拉高 `valid` 一周期 |

**为什么最后还要 HOLD 和 GAP？**

- `HOLD`：MCP3208 手册要求最后一个时钟之后 CS 不能立刻拉高，芯片需要一个最小时间来完成内部转换。
- `GAP`：保证两次读取之间有 CS 高电平间隔，让芯片可靠复位到待机。

### 两个设计要点

**① `valid` 只持续一个主时钟周期**

```verilog
valid <= 1'b0;              // 每个时钟先默认拉低
...
valid <= 1'b1;              // 只在完成时拉高一次
```

这样下游看到的是一个**干净的单周期脉冲**，而不是一个一直高着的电平——后者会让下游分不清"这是新数据"还是"还是上次那个数据"。

**② `data` 会保持**

`data` 一直保持上次的结果，直到下次读取完成。所以下游随时来读都能读到有效值，不必非要在 `valid` 那一刻读。

### 为什么 `busy` 期间要忽略新请求

```verilog
IDLE: begin
    if (start) begin ... end     // 只在 IDLE 响应 start
end
```

`SHIFT` 状态完全没有检查 `start`，所以**忙的时候新请求自动被忽略**：既不打断当前事务，也不会排队等会儿偷偷执行。

这是**刻意的设计**。如果排队，就会出现"按了一下，过一会儿突然又响一下"的怪现象。测试台专门验证了这一点。

### 端口总表

| 信号 | 方向 | 含义 |
|---|---|---|
| `clk` | 输入 | 50 MHz 主时钟 |
| `rst_n` | 输入 | 低电平有效复位 |
| `start` | 输入 | 拉高一个主时钟周期即发起一次读取 |
| `miso` | 输入 | ADC 返回的数据 |
| `cs_n` | 输出 | 片选，低电平有效 |
| `sclk` | 输出 | 500 kHz SPI 时钟 |
| `mosi` | 输出 | 发给 ADC 的命令 |
| `busy` | 输出 | 正在读取，此时忽略 `start` |
| `data[11:0]` | 输出 | 12 位结果，保持到下次读取完成 |
| `valid` | 输出 | 新结果有效，只持续一个主时钟周期 |

## 5. 测试文件：一个"假扮 ADC"的演员

测试台里其实藏了**两个角色**。

### 5.1 角色一：假扮 ADC

```verilog
always @(negedge cs_n) begin
    latched_value = model_value;      // CS 一拉低，锁定这次要回的答案
    rising_count  = 0;
end

always @(posedge sclk) begin          // 数你一共嗒了几下
    rising_count = rising_count + 1;
end

always @(negedge sclk) begin          // 按位把 12 位吐回去
    miso <= #200 latched_value[23-rising_count];
end
```

**注意：这段代码没有连接任何真实芯片。** 它就是测试文件里的一个变量在按剧本吐数据。

### 5.2 角色二：假考官（断言检查）

它在一边盯着，一旦发现违规就 `$fatal` 直接判死：

| 检查项 | 违规后果 |
|---|---|
| SPI 半周期必须是 1000 ns | 频率不对 |
| 每次事务必须恰好 24 个时钟 | 少发/多发 |
| 拼接出的命令必须是 `060000` | 命令错 |
| SCLK 结束时必须是低 | Mode 0 违规 |
| `valid` 不得持续超过一个主时钟周期 | 下游会读错 |
| `valid=1` 时 `busy/cs_n/sclk` 必须符合约定 | 状态不一致 |
| 命令与时钟数独立复核 | 防止驱动自己"作弊" |

最后一条很重要：**测试台不信任驱动报出来的结果，而是自己去数 SCLK、自己拼接 MOSI**，独立验证一遍。这叫"独立参考模型"，是数字验证的基本手法。

### 5.3 五个测试值各自查什么

| 测试值 | 二进制 | 想抓的毛病 |
|---|---|---|
| `000` | `0000 0000 0000` | 全零能否读对 |
| `001` | `0000 0000 0001` | **最低位 B0 会不会丢**（最容易犯的错） |
| `555` | `0101 0101 0101` | 交替位；**位序错或整体错位一位立刻暴露** |
| `AAA` | `1010 1010 1010` | 交替位反向，与 `555` 互补验证 |
| `FFF` | `1111 1111 1111` | 12 位是否收满、会不会少一位 |

**为什么 `555` 和 `AAA` 特别有用？** 如果接收窗口偏了一位，`0101…` 会变成 `1010…`，两个值直接互换——一眼就能看出是错位而不是数据错。

### 5.4 三个异常场景

| 场景 | 期望行为 |
|---|---|
| 事务进行到一半复位 | 取消当前读取，回到空闲，**不发布结果** |
| 复位后再次读取 | 能正常工作（`A55` 读对了） |
| `busy` 期间再发请求 | **被忽略**：不打断当前事务，也不排队执行 |

### 5.5 两条安全网

- **超时保护**：`#2000000; $fatal("Simulation timeout")` —— 防止仿真死等 `valid` 永不结束。
- **数据保持检查**：`valid` 之后等 3 个时钟，确认 `data` 没被改动。

## 6. 波形报告怎么读

`sim/waveform_check.txt` 是脚本 `sim/check_waveform.ps1` 读 VCD 文件生成的**可读表格**——把"画在波形图上的线"翻译成"一眼能看懂的表"。

### 6.1 VCD 信号代号对照

脚本靠 VCD 里的短代号认线：

| VCD 代号 | 信号 | 出现在 testbench 的哪一行 |
|---|---|---|
| `%` | `cs_n` | 第 12 行 |
| `"` | `sclk` | 第 13 行 |
| `#` | `mosi` | 第 14 行 |
| `*` | `miso` | 第 10 行 |
| `+` | `model_value` | 第 32 行 |
| `$` | `data` | 第 17 行 |
| `!` | `valid` | 第 18 行 |
| `-` | `rst_n` | 第 8 行 |
| `&` | `busy` | 第 16 行 |

**两个名字不一致的地方，原因如下：**

| 报告里的名字 | 真名 | 为什么改名 |
|---|---|---|
| `expected` | `model_value` | 这是测试台里"这次准备返回什么数"，**同时也是考官手里的标准答案** |
| `miso_payload` | `miso` | payload = 载荷/有效内容。MISO 上一直有电平，但只有第 13～24 个时钟的 12 位才算有效数据 |

### 6.2 报告里的字段含义

```text
#3 start=100.29 end=149.29 expected=555 clocks=24 period_us=2 half_us=1 command=060000 miso_payload=555 reset=False
```

| 字段 | 含义 |
|---|---|
| `#3` | 第 3 次事务 |
| `start` / `end` | CS 拉低到拉高的时刻（微秒） |
| `expected` | 测试台这次准备返回的值 |
| `clocks` | 这次事务的 SCLK 上升沿个数（应为 24） |
| `period_us` | SCLK 周期（应为 2 µs） |
| `half_us` | SCLK 半周期（应为 1 µs） |
| `command` | 实际从 MOSI 上拼出来的命令（应为 `060000`） |
| `miso_payload` | 实际从 MISO 上拼出来的 12 位数据 |
| `reset` | 这次事务是否被复位打断 |

### 6.3 本次实际结果

8 次事务，7 个 valid 脉冲：

| # | 时间(µs) | 期望值 | 时钟数 | 命令 | 收到 | 备注 |
|---|---|---|---|---|---|---|
| 1 | 0.13–49.13 | `000` | 24 | `060000` | `000` | |
| 2 | 50.21–99.21 | `001` | 24 | `060000` | `001` | 最低位不丢 |
| 3 | 100.29–149.29 | `555` | 24 | `060000` | `555` | 位序正确 |
| 4 | 150.37–199.37 | `AAA` | 24 | `060000` | `AAA` | 位序反向 |
| 5 | 200.45–249.45 | `FFF` | 24 | `060000` | `FFF` | 12 位收满 |
| 6 | 250.53–269.54 | `123` | 10 | partial | partial | **中途复位，事务被取消** |
| 7 | 329.67–378.67 | `A55` | 24 | `060000` | `A55` | 复位后恢复 |
| 8 | 379.75–428.75 | `321` | 24 | `060000` | `321` | busy 请求被忽略 |

`VALID PULSES`：7 次 `valid` 宽度**均为 20 ns**（= 50 MHz 一个周期），且拉高时 `busy=0`、`cs_n=1`、`sclk=0`。

**两个来源互相验证：**

- 终端：`$finish called at 489740000 (1ps)` → **489.74 µs**
- 报告：`end_us=489.74`

**完全一致**，说明终端结果和波形文件出自同一份源码。

### 6.4 `half_us=0.01,1` 是什么（可以忽略）

第 6 行出现了异常值 `0.01`。**这不是 bug，是测量假象。**

复位发生在第 10 个时钟、SCLK 还处于高电平时，`rst_n=0` 把它立刻打回低。这一下在 VCD 里被记成一个"额外边沿"，脚本算出两次边沿间隔 0.01 µs。

真正的 testbench 检查器里有门控（`if (rst_n && !cs_n)`），**复位期间不检查**，所以没有误报。而 `check_waveform.ps1` 没有等价的复位过滤，才漏出这个数。

## 7. 为什么这 200 ns 延迟很重要

测试台里这句是刻意设计的：

```verilog
miso <= #200 latched_value[23-rising_count];
//         ↑ 200ns 延迟
```

**如果改成 `#0`（立即响应），仿真大概率还是 PASS。那为什么非要加？**

因为这 200 ns 模拟的是**真实芯片的响应延迟**：真实 MCP3208 收到时钟下降沿后，不可能瞬间把数据摆到 DOUT 上，需要一段时间（手册里叫 `tDO` 等参数）。

**如果假 ADC 零延迟，"数据摆稳"和"你采样"就发生在同一瞬间。** 这种理想情况在真实硬件上不存在，会让"采样时刻太早、数据还没稳定"的缺陷也照样 PASS——**测试就失去了意义**。

> **核心观念：这个假 ADC 不是"越完美越好"，而是"越像真芯片越好"。**

这也是数字验证里"**理想模型会掩盖问题**"的典型例子：测试环境太宽松，等于没测。

## 8. 仿真通过 ≠ 实物通过

今天的成功判据**只是电脑里的 PASS 和正确波形**。

| 项目 | 状态 |
|---|---|
| 真实 MCP3208 芯片通信 | ❌ 未做 |
| 真实压力片读数、轻重按数据 | ❌ 未做 |
| 3.3 V 供电、分压电路、接线 | ❌ 未做 |
| 八通道扫描 | ❌ 未做 |
| 力度映射（→ 0～65535 增益） | ❌ 未做 |
| 上板综合、下载、码流 | ❌ 未做 |
| 整机延迟 | ❌ 未做 |

### 假 ADC 没模拟的东西

- **真实电压 → 数字的转换过程**（假 ADC 直接给数，跳过了模拟部分）
- VREF 参考电压、源阻抗、去耦要求
- 真实的采样保持时间、芯片自身的建立时间
- **CH1～CH7**（假 ADC 只会 CH0）
- 输入超范围、供电异常、芯片没接好时的表现

**所以"仿真通过"只证明协议层对了，不证明电气层对了。**

## 9. 上实物需要补什么

### 9.1 三个文件分别怎么办

| 文件 | 上实物时怎么办 | 原因 |
|---|---|---|
| `src/adc_ch0.v` | ✅ **原样保留，一行都不用改** | 本来就是为硬件写的 RTL，无仿真专用语法 |
| `tb/tb_adc_ch0.v` | ❌ **不能上板，整个丢掉** | 里面全是仿真语法 |
| — | 🆕 **新写一个 top** | 现在完全没有 |
| — | 🆕 **新写 CST / SDC 约束** | 现在完全没有 |

### 9.2 为什么测试台不能"改一下"

```verilog
$dumpfile("sim/adc_ch0.vcd");   // 写波形文件，硬件上不存在
$fatal(1, "...");               // 报错退出，硬件上没有控制台
initial begin ... end           // 只在仿真开始执行一次，综合器直接忽略
wait (valid === 1'b1);          // 仿真语法，综合器不认识
#10 clk = ~clk;                 // 延时语句，综合器不认识
```

**它的角色是"扮演 MCP3208"。真芯片上场了，扮演者就退场。这不是改造，是替换。**

### 9.3 top 必须做的四件事

`adc_ch0` 是个**子模块**，只有 `clk / rst_n / start` 三个输入，不会自己动。上板必须有人给它这些：

1. **提供 50 MHz 时钟**（板载晶振）
2. **每 1 ms 产生一次 `start` 脉冲** —— ⚠️ 关键是脉冲，不能一直拉高
3. **`valid` 到来时把 `data` 存下来**
4. **把存下来的数"露出来"给人看**

> ⚠️ 关于第 2 点：驱动在 `busy` 期间会忽略 `start`，所以一直拉高不会出错，但会让读取一次接一次不间断地跑，你就没法控制采样节奏了。这是上板时第一个会踩的坑。

### 9.4 约束文件

```text
xxx.cst  → 引脚约束：clk、cs_n、sclk、mosi、miso 各接哪个物理脚
xxx.sdc  → 时序约束：告诉工具主时钟是 50 MHz
```

> ⚠️ **引脚号不能猜。** 板子上同时有 **1.5 V 和 3.3 V** 的 I/O Bank。SPI 外接脚必须选**已核实为 3.3 V 的空闲扩展 GPIO**，并检查"底板接口位置、FPGA 球号、Bank 电压、CST 信号名"四者一致。
> **接错 Bank 会把 3.3 V 灌进 1.5 V 的脚，可能烧掉 FPGA。** 必须和 A 一起核对。

### 9.5 怎么把数字"读出来看"（最容易被忽略）

仿真里能 `$display` 打印，**实物上没有这个**。目前只有机械万用表（无逻辑分析仪、无示波器），必须选一条路：

| 方法 | 可用性 | 说明 |
|---|---|---|
| 串口发到电脑 | ✅ 推荐 | 需先确认板载串口路由，不能假定插上 USB 就能读 |
| 逻辑分析仪 | ⚠️ 需借用 | 能直接解码 SPI，不必先写串口 |
| LED 显示高几位 | ✅ 可以 | 只能看"低/中/高"档位，**无法做校准** |

> ⚠️ 那个 **20 ns 的 `valid` 脉冲，肉眼和 LED 都看不见**。必须靠 top 把它存下来再显示。

### 9.6 建议的动手顺序

```text
1. 先别碰 ADC
   └─ 用现有成功的 Gowin 工程，只做一件事：把 50MHz 分频，让一个 LED 按 1 秒闪
      （证明"我能建工程、能定引脚、能下载、能看现象"）

2. 再加 top：每 1ms 发 start，把 data 存下来
   └─ 此时 ADC 还没接，miso 悬空 → 读到全 0 或乱数，都正常

3. 接 ADC 供电（先不接信号）
   └─ 万用表确认芯片脚上的 VDD / VREF / GND

4. CH0 接 GND            → 应读到接近 0
   CH0 接 2kΩ+2kΩ 分压中点 → 应读到接近 2048
   CH0 接 3.3V            → 应读到接近 4095

5. 通过第 4 步，才接压力片
```

**第 4 步是分水岭。** 三档读数都合理，说明 SPI 通路、位序、接线全对了，这时候才值得去关心压力的轻重。

预期码值可按实测电压计算：

```text
预计码值 ≈ 4096 × V_CH0 / VREF    （限制在 0～4095）
```

### 9.7 上板后最可能出问题的顺序

按概率排列，**没一个是驱动的问题**：

1. **引脚 / Bank 电压搞错** → 综合能过，但不工作或损坏
2. **接线错**（DIN/DOUT 接反最常见 → 读回全 0 或全 1）
3. **top 的 start 时序写错**（一直拉高、或没等 busy 就发）
4. **VREF/VDD 没接好** → 读数乱跳
5. **SPI 速度** → 500 kHz 很慢，基本不是问题

这正好印证"把 SPI 问题与传感器问题分开"：**今天已经把第 5 类排除了，上板时只剩前 4 类。**

## 10. 踩过的坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `Unable to open input file` | 不在工程目录下运行，相对路径失效 | 先 `Set-Location` 到工程目录，或用绝对路径 |
| 波形文件找不到 | testbench 里 `$dumpfile("sim/adc_ch0.vcd")` 是相对路径，写到了别的目录 | 同上 |
| `half_us=0.01,1` | 复位时 SCLK 被立即拉低，脚本记录到额外边沿 | **测量假象，可忽略**；真实 testbench 有复位门控 |
| `sim/` 下有多个 `.vvp` | 中间过程产物 | 对外提交时说明哪个是最终版本，避免源码与证据不对应 |

### 判断"真通过"的唯一标准

必须是终端里出现这 9 行，**尤其是最后一行**：

```text
PASS value=000
PASS value=001
PASS value=555
PASS value=aaa
PASS value=fff
PASS reset-abort
PASS value=a55
PASS busy-ignore
PASS: all CH0 tests completed      ← 关键
```

**原因**：`$fatal` 一旦触发会**立即终止仿真**，最后一行的 `all CH0 tests completed` 就永远不会打印。所以它的出现本身就证明所有断言检查全部通过。

⚠️ **容易"看起来过了其实没过"的坑**：`$fatal` 终止仿真后，**已经写进 VCD 的前半部分还在**，所以波形报告照样能生成完整的表格。**不能只看波形文件下结论。**

### 记忆要点

```text
使用50MHz主时钟，生成500kHz SPI时钟。
采用Mode 0，固定读取单端CH0。
发送0x06、0x00、0x00，接收12位结果。
复位会取消当前事务；busy期间的新请求被忽略。
（附加）仿真输出与VCD波形解析结果一致：8次事务、7个valid脉冲、结束时刻489.74us。
```

## 11. 下一步（D3）：扩为八路扫描

1. 命令字由通道号计算，不再写死常量（每通道 `+0x08`）
2. 加入通道计数器，一轮扫描 CH0～CH7
3. 每通道一份影子寄存器，**一轮扫完再整体发布**（避免下游拿到不同时刻的采样值）
4. 屏蔽未安装通道
5. 测试：8 路放不同测试值，验证连续扫描不串号、不丢结果、复位不发布半帧

**时间预算**：当前一次事务约 49 µs，8 路约 392 µs，加间隙仍小于计划要求的 1 ms 一轮。若需提速，`HALF_CYCLES` 从 50 降到 25 即为 1 MHz。

**需协调**：与 A 确认仿真环境路径、以及最终 `adc_spi` 模块的端口命名（便于总 top 集成）。D3 为纯 RTL 工作，不占用板卡。
