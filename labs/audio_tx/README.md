# I2S 发送模块与时序说明

日期：2026-10-11

本目录包含 `audio_tx.v` 和 `audio_tx_tb.v`。当前模块发送 16 位音频样本，左右声道使用同一个样本。固定输入 `16'h1234` 的仿真已通过时钟检查，输出波形也已按外部 BCLK 和 WS 解码核对。

## 时钟参数

| 项目 | 数值 |
|---|---|
| 主时钟 `clk` | 50 MHz，周期 20 ns |
| BCLK | 3.125 MHz，周期 320 ns |
| BCLK 高、低电平时间 | 各 160 ns |
| 每声道长度 | 32 个 BCLK，10.24 μs |
| 每帧长度 | 64 个 BCLK，20.48 μs |
| 采样率 | 48828.125 Hz |

采样率由 50 MHz 分频得到，并非严格的 48000 Hz。所有内部寄存器由主时钟驱动，BCLK 作为输出信号。

## 模块接口

| 信号 | 方向 | 位宽 | 作用 |
|---|---|---|---|
| `clk` | 输入 | 1 | 50 MHz 主时钟 |
| `rst_n` | 输入 | 1 | 低电平有效的异步复位 |
| `sample_data` | 输入 | 16 | 待发送的音频样本 |
| `bclk` | 输出 | 1 | I2S 位时钟 |
| `ws` | 输出 | 1 | 低电平为左声道，高电平为右声道 |
| `din` | 输出 | 1 | I2S 串行数据 |
| `sample_ce` | 输出 | 1 | 请求下一帧样本的脉冲 |

## I2S 数据格式

WS 和 DIN 在 BCLK 下降沿更新，接收端在 BCLK 上升沿读取。

每个声道占 32 个 BCLK。下表从 WS 切换后的第一个 BCLK 上升沿开始计数。

| 上升沿序号 | 接收内容 |
|---|---|
| 1 | 延迟位，当前输出 0 |
| 2 至 17 | D15 至 D0，最高位先发送 |
| 18 至 32 | 15 个补零位 |

同一帧的左右声道发送相同的锁存样本。帧中途改变 `sample_data` 不会改变该帧的锁存数据。

## 给音频计算模块的时序约定

`sample_ce` 每帧产生一次，持续一个主时钟周期，即 20 ns。复位释放后首次产生请求时，发送模块开始发送首帧零数据。

| 时间点 | 发送模块行为 | 音频计算模块需要完成的工作 |
|---|---|---|
| 首帧开始 | 输出零样本，并产生第一次 `sample_ce` | 收到请求后计算第二帧样本 |
| 下一帧开始前 | 继续发送当前帧的锁存数据 | 将计算结果放到 `sample_data`，并保持到锁存完成 |
| 下一帧开始 | 锁存此前准备好的 `sample_data`，同时产生下一次请求 | 根据新请求计算再下一帧样本 |
| 当前帧发送期间 | 左右声道都使用该帧锁存的样本 | 可以准备下一帧的数据 |

两次请求的间隔为 1024 个主时钟周期。计算模块若在主时钟上升沿读取 `sample_ce`，会在脉冲拉高后的下一个上升沿识别请求，不能把这段间隔全部当作可用计算时间。

**结果必须在下一帧的锁存上升沿之前稳定。** 如果计算模块在锁存上升沿才用非阻塞赋值更新 `sample_data`，发送模块会读取更新前的值。

当前接口没有 `mixed_valid`、结果缓冲或超时检测。后续接入计算模块时，需要一起确定结果有效信号和缓冲方式。

## 仿真方法与结果

在本目录中运行以下命令。当前测试代码使用普通 Verilog，不需要 `-g2012`。

```sh
iverilog -s audio_tx_tb -o audio_tx_sim.vvp audio_tx.v audio_tx_tb.v
vvp audio_tx_sim.vvp
```

测试输入固定为 `16'h1234`。当前 testbench 自动检查复位输出、BCLK 和 WS 时序。数据和请求脉冲通过读取生成的 `audio_tx_tb.vcd` 另行核对。

| 检查项 | 结果 |
|---|---|
| 首帧左、右声道 | 均为 `16'h0000` |
| 第二帧左、右声道 | 均为 `16'h1234` |
| 每声道长度 | 32 个 BCLK |
| 延迟位及末尾补零 | 正确 |
| WS 和 DIN 更新时刻 | BCLK 下降沿 |
| `sample_ce` 宽度 | 20 ns |
| `sample_ce` 间隔 | 20.48 μs |

当前结论仅覆盖固定样本仿真。后续还需要增加独立 I2S 接收测试，检查更多数值和帧中途改变输入的情况，并进行上板验证。
