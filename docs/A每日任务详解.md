# A 每日任务详解：标准 I2S、总工程与验证

更新：2026-10-10。按仅有数电/Verilog基础编写。配合[总计划](三人分工与交付计划.md)、[接口](接口约定.md)、[交接记录](交接与验收记录.md)。日期是目标，实际未过先修；假数据验证与真实发声分开记录。

## 你负责的链路是什么

队长交给你16位声音数字，你负责按规定时序送出去；B交输入模块，你负责连接总top。A不负责写合成算法，也不替B处理原始压力。

| 名称 | 含义 |
|---|---|
| BCLK | 数字音频传每一位的时钟；目标3.125MHz |
| LRCLK/WS | 左右声道时隙标志；一整周期一组采样 |
| DIN | FPGA送给功放的串行声音位 |
| I2S一位延迟 | WS改变后一个位周期才开始该声道的MSB |
| sample_ce | 请求核心计算下一帧的脉冲 |
| 缓冲 | 核心结果暂存，下一帧装载发送 |
| CST/SDC | 物理引脚/电气约束与时钟/时序约束 |

主时钟50MHz，每8周期翻转一次BCLK，完整BCLK周期16主时钟；64个BCLK一组左右音频，因此sample_ce间隔1024主时钟。Fs=48,828.125Hz，不能记录成精确48kHz。

MAX98357A输入标准I2S，不是旧PT8211格式。用[官方手册](https://www.analog.com/media/en/technical-documentation/data-sheets/MAX98357A-MAX98357B.pdf)核对一位延迟、数据边沿、位数、时钟比及模块使能；电源和引脚仍按实物DFR0954说明检查。时序不懂时先画图，不能靠“听起来有声”确认位序。

## 10/10：从空工程独立点灯

**学什么：** 源文件、顶层、器件型号、约束、综合/布局布线/码流之间的关系。

**具体做：**
1. 记录板卡和底板版本、FPGA型号、Gowin版本，查实际原理图和GPIO Bank电压。
2. 新建练习工程，只放时钟/复位/计数器/LED，选择已核对的LED引脚。
3. 添加.v、CST、时钟约束，设置top；依次综合、布局布线、生成.fs、下载。
4. 做一次源码小改再重建，确认下载的是新码流；保存日志、工程和对应版本。
5. 与B查看可供ADC和外接I2S使用的3.3V GPIO，先填接线候选，不贸然上电。

**验收/交接：** 不靠别人代建工程也能点灯；能解释哪些文件是源码/配置、哪些是产物。交三人工具版本和构建流程，B协助核对接线。

## 10/11：先做音频时钟与固定发送

**学什么：** 计数器分频、串行移位、I2S时隙和一位延迟。

**具体做：**
1. 在纸上画64个BCLK的左右帧，标WS转换、D15…D0以及零填充位置。
2. 以接收端看到的WS转换作为新时隙标志，MSB在下一位开始；别把“填零”写成少传一位。
3. 所有内部寄存器先在50MHz域工作，BCLK是受控输出，避免把它随意用作第二逻辑时钟。
4. 做audio_tx初版，先输入固定16位字，例如16'h1234，保持整个帧的样本不变。
5. 给队长时序表：请求什么时候发、结果什么时候最晚到、下帧什么时候装载；确认复位首帧零。

**验收/交接：** 仿真BCLK周期320ns，完整帧20.48µs，左右各32位。交队长sample_ce时序，暂不以此证明真实输出成功。

## 10/12：写真正的 I2S 接收 testbench

**具体做：**
1. 接收器在BCLK采样边沿观察DIN，看到WS变化后跳过延迟位，再收16个有效位；记录剩余填充。
2. 独立解码发送流，与输入序列比较，不简单复用发送器的内部bit_index逻辑作预期。
3. 测0、16'h0001、16'h1234、16'h7FFF、16'h8000、16'hFFFF和正负交替，错误即报出帧/声道/期望/实际。
4. 在发送半帧时改变上游输入，确认一帧内锁定样本、不半途撕裂；先不给下一帧缓冲做复杂优化。
5. 联系实验室借示波器，明确10/24需要真实压力输入与功放输出测延迟；先问能否做差分Class D音频测量。

**验收/交接：** 左右均正确、一位延迟与符号正确、无缺位/多位；交队长发送器接口和可重复测试。借仪器记录设备/联系人/可用日期，尚未借到就写未落实。

## 10/13：MAX98357A 和喇叭低幅上板

**具体做：**
1. 与B断电核对模块电源、地、BCLK/LRCLK/DIN、使能和声道配置，确认GPIO是适当3.3V Bank。
2. 按实物说明接喇叭到两输出端，不能把任一输出当地；不要把功放输出接电脑声卡输入。
3. 先零数据，确认没有错误大输出；再用低幅正弦或测试音，逐步提高幅度。
4. 发送时钟持续，音量用数字采样控制，不通过按键反复开关功放。
5. 保存实物接线照片、CST、SDC、工程与实际采样率；不照搬旧板载PT8211引脚。

**验收/交接：** 稳定发声、零样本静音；参考板载输出与标准I2S证据分别记录。交队长“输出链已独立通过”和有效接法，B固定接线。

## 10/14：连接真实一键并完成下一帧缓冲

**具体做：**
1. 创建总top，连接B的CH0控制与队长单声部，其余gate/gain为零。
2. 接到mixed_valid时存下一帧缓冲；帧边界装载此前结果再发下一请求，第一帧零。
3. 记录哪次请求对应哪次发送，不能同沿更新寄存器却认为读取到新值。
4. 一次只替换一段排错：固定采样查输出、假控制查核心、真实控制查输入。

**验收/交接：** 真实一键压力控制实时声音，版本、码流、接线和演示归档；A维护此可运行版本，不让后续修改覆盖唯一成功副本。

## 10/15：检查缓冲、缺帧和复位

**具体做：** testbench人为改变核心valid延迟，覆盖及时返回、未返回、复位中、首帧。缺帧发送零并增加诊断计数，不能继续旧样本掩盖问题；正常返回的样本顺序不变。复位保持可预测的静音起步。

**验收/交接：** sample_ce每1024周期一次，结果与帧一一对应，故意迟到可被发现；交队长最晚期限和缓冲时序，给三人排错方法。

## 10/16：单声部 ADSR 集成

**具体做：** 接队长voice，用假gate做按住/松开/重按，再接真实CH0。检查波表和包络依赖、计算周期，保证data/valid在发送期限前到。听感突然静音时查gain冻结，不先改I2S。

**验收/交接：** 声音起落完整，release不截断，时钟和帧连续；交队长可复现异常与相应输入，不只录一段杂音。

## 10/17：建立四键总工程

**具体做：** 把前四键、四声部和audio_tx接top，后四键零。源码列表区分RTL与testbench，表初始化路径可重建。加入观察数据：控制帧、核心valid、缺帧计数、模式；先仿真总链路再上板。

**验收/交接：** 四键假数据仿真通过、综合/布局布线可运行；交B待上板版本和固定接线，交队长资源/时序结果。

## 10/18：主持四键实物验收

**具体做：** 逐键、两键、四键、只松第二键、改变一键力度。控制帧正确但声音错误交核心；原始通道错交B；解码帧错由A修。记录期待/实际和版本，故障隔离后再修改。

**验收/交接：** 四真实键、ADSR、独立力度、正常无缺帧；保存通过版及问题清单。

## 10/19：用假八键提前验证负载

**具体做：** 无需等B完成后四键，用八位gate和八组固定gain连接队长八声部。检查请求至valid周期、帧连续、资源变化及是否出现时序失败。若波表结构变化，核对源码/表初始化列表。

**验收/交接：** 八声部假控制输出稳定，核心结果仍在期限内；交队长资源/时序瓶颈，不自己改算法。

## 10/20：八键综合、下载与输出余量

**具体做：** 接B完整八键帧，逐通道核对映射。先低幅测试，检查八音同时是否明显削波；与队长核对固定除八，不按键数增益突变。确认下载.fs来自本次构建，日志和版本一起保存。

**验收/交接：** 八键可运行，时序结果已检查，无缺帧；交三人实际构建和下载记录。

## 10/21：八键联合验收

**具体做：** 执行总清单：八键同按、逐路松开、力度独立、复位、上电。每项记录输入/结果，不只拍同时有声音的视频。发现失败用已通过四键版对照定位，保留测试证据。

**验收/交接：** 八键八声部节点签核，版本归档；尚未通过项有负责人。

## 10/22：功能键与模式集成

**具体做：** B的事件接队长参数逻辑，普通用户键与复位/下载键区分。观察默认正弦、原始音区、演奏模式；长按、重复按、两键同按检查。用LED或调试寄存器显示状态，不扩成复杂屏幕系统。

**验收/交接：** 音色/音区/测试变化可重复，状态与声音一致；交B/队长操作说明和故障输入。

## 10/23：频谱与测量准备

**具体做：**
1. 用队长给的四个非整数倍纯正弦频率和固定增益测试；测试top的test_mask映射到现有八键gate控制帧，不给正式接口加新的随意端口。
2. 全开录制，再逐路关闭，比较相应频点；记录采样设备、采样率、窗口、频率分辨率和环境。
3. 手机/电脑录音可做辅助，不把录音时间轴当精准控制延迟。
4. 确认借到仪器、探头、实验室差分测法和音频恢复/滤波；B准备输入触发点、真实模式和校准阈值。

**验收/交接：** 四声部证据可辨认；测量条件落实，未落实有明确阻塞记录。

## 10/24：真实总延迟测量

**具体做：**
1. 用真实演奏模式，记录扫描、平滑、ADSR和源码版本。
2. 按实验室确认方法同时观察输入分压和实际音频输出，输入阈值和输出幅度判据在测量前写明。
3. Class D两端不是地，普通示波器地夹不接扬声器任一端；确认差分和滤波链路延迟。
4. 覆盖不同通道、轻重输入、扫描时刻，至少每个代表条件重复10次，保存原始波形与最大值，边界结果考虑不确定性。
5. 内部valid只能辅助定位；没设备或测法未确认就填未实测，不冒写通过。

**验收/交接：** 可复现测量记录、最大延迟和不确定性；超10ms由对应模块负责人修、整链重测。交队长用于报告，B核对输入条件。

## 10/25：整机稳定性与功能冻结

**具体做：** 30分钟按放/和弦/压力/模式测试，记录缺帧、错误、死机或杂音；复位/重新上电/搬动后再演奏。检查综合/布局报告和所有约束警告，不仅看是否生成.fs。

**验收/交接：** 冻结一版真实可用工程，未通过项列负责人；之后只修问题，不追加大功能。

## 10/26：写输出和工程章节

**具体做：** 画I2S帧、一位延迟、采样请求/返回/缓冲/装载时序，解释实际Fs、bit数、左右复制与缺帧策略；列工具版本、top、源码和约束。

**验收/交接：** 图与代码一致，说明标准I2S而不是混称PT8211；交队长复核，保留图源文件。

## 10/27：整理频谱、延迟和时序资源证据

**具体做：** 每张图配版本、设置、操作、预期/实际、结论。资源和时序来自实际最终工程；延迟只引用实测，不能把L×20ns当整机延迟。三人章节初稿汇总，技术不懂处问负责人。

**验收/交接：** 报告结论有来源，待测明确；队长复核核心，B复核硬件。

## 10/28：另一电脑重建

**具体做：** 复制/克隆完整交付源码到干净目录，工具版本匹配；从零打开工程、添加必要表、综合/布局/生成码流；不依赖原电脑绝对路径或缓存。记录全过程，能上板时用新码流复验。

**验收/交接：** 真实重建成功，缺文件/路径问题已解决，实际测试与仅构建分别记录。

## 10/29：汇总构建与交付清单

**具体做：** 写启动/构建/下载/运行步骤；整理源码提交号、码流、波表、接线、校准、测量和报告对应表。让队长/B逐项核对，不擅自修改其技术结论。

**验收/交接：** 另一人按说明可重现；未测項和限制保留。

## 10/30：拍摄与剪辑

**具体做：** 依次录八键、松一路、单键力度、音色/变调、频谱/延迟证据、上电演示。B操作，队长解释核心；保留实物声音，不用后期预录音替换。画面能看清动作与设备。

**验收/交接：** 视频版本与码流一致，关键功能没有剪掉失败条件或混入旧测试。

## 10/31：答辩练习

**具体做：** 回答I2S为何有一位延迟、Fs如何计算、valid何时接收、为什么需要缓冲、延迟如何实测、怎样重建。现场故障准备固定音源/假控制排错，但不把调试模式当正式演示结果。

**验收/交接：** 与队长/B互问，修说明不一致；准备演示操作清单。

## 11/1：最终演练与备份

**具体做：** 从上电开始整场演示；整理源码包、码流、视频、报告、证据、工具说明；本地和另一介质备份。检查默认模式、输入连接、供电和版本号。

**验收/交接：** 不现场改代码也能演奏，备份可打开。

## 11/2：核对正式平台要求

**具体做：** 查看正式文件格式、大小、命名、时限；按要求打包。不擅自把被.gitignore忽略的码流漏出交付包；Git忽略规则与比赛交付要求分别处理。任何核心修复通知重建复测。

**验收/交接：** 提交目录完整且版本一致，队长签核技术，B签核接线材料。

## 11/3：上传与复查

**具体做：** 按授权与平台流程提交，确认状态，再下载核对文件完整、视频可播放、报告可打开；保存提交凭证和时间。上传失败保留错误并尽早处理，不等截止点。

**验收/交接：** 正式提交成功的凭证交三人，不能只凭点击上传宣称成功。

## 11/4：必要修正与现场支持

**具体做：** 仅修格式/漏文件/已定位问题，确认新提交状态与备份；支持演示。若换源码/码流，重新核对相关功能和报告。

**验收/交接：** 最终状态和版本清楚，不开展大改。

## 常见故障定位顺序

没声音：供电/使能→固定样本I2S→实际核心valid/缓冲→gate/gain。音高不对：Fs与step。噪声或失真：符号/位序/一位延迟/幅度/供电。随机断音：缺帧计数与装载期限。每一步记录版本和结果，不让三人同时无记录改同一个top。
