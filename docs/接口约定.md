# 开始并行开发前确认的接口

状态：建议草案，三人确认后固定；端口名不是赛方规定。主时钟先沿用 50MHz，实际音频采样率由 A 按最终发送时序计算。不要把原实验的 48,828.125Hz 误写为精确 48kHz。

| 信号 | 来源与接收 | 约定 |
|---|---|---|
| clk、rst_n | A 总工程 → 全部模块 | 同一主时钟域；统一复位方向和释放 |
| sample_ce | A → 队长核心 | 一主时钟周期请求，一组音频采样一次；明确请求对应哪一帧 |
| gate[3:0] | B → 队长 | 1=按住，已同步，可多位同时为1 |
| pressure_gain[15:0] | B → 队长 | 无符号，0=零增益，65535≈单位增益；无压力/复位初值共同决定 |
| button_events | B → 队长 | 功能事件，需约定保持/接受方式，不丢单周期事件 |
| mixed_sample[15:0] | 队长 → A | 16位有符号二进制补码 |
| mixed_valid | 队长 → A | 输出有效；固定运算延迟，发送装载前完成 |

A 与队长先画一次采样的时序表：请求→核心计算→缓冲→发送。简单起步可生成下一帧所需数据，首帧为零。模块更新发生在同一沿时，不能默认下游已读到新寄存器值。

独立验证：队长用假 gate/压力与采样使能；A 用指定采样数字；B 用仿真 ADC 和 LED/数据输出。假数据开发成功后必须补真实硬件联调。

待确认：实际采样率、核心运算延迟、事件接受机制、默认力度、最终 DAC 和接线。
