# 队长每日任务详解：从 DDS 到八声部合成核心

更新：2026-10-10。读者只有数电和 Verilog 基础。与[总计划](三人分工与交付计划.md)、[接口约定](接口约定.md)、[交接记录](交接与验收记录.md)一起使用。日期为目标，不是完成声明；落后时从最后一个未通过任务继续，先保住闭环，再追赶扩展。

## 怎样使用本手册

你每天完成四件事：理解当天原理；做一个小模块或明确修改；用可重复输入验证；把产物与接法交给 A。不会的术语先查本文说明，不要求一次学完 DSP。

| 术语 | 在项目里的含义 |
|---|---|
| 主时钟 | 50MHz，寄存器按这个节拍工作，一个周期20ns |
| 采样使能 | sample_ce为1的那个主时钟沿，启动一组声音运算；每1024周期一次 |
| 相位 | 波形一圈走到哪里，32位整数自然回绕 |
| 频率字 | 每次采样前进多少相位，决定音高 |
| 包络 | 音量随按下、保持、松开变化的曲线 |
| 定点增益 | 用整数表示0～1，乘完后缩放回声音位宽 |
| valid | 这一拍数据可以接收，必须与对应采样对齐 |

默认从项目根目录运行仿真。可用如下方式运行现有 DDS 测试；模块端口修改后必须同时更新 testbench。命令是练习入口，不表示当前文件已经通过新版功能。

```powershell
iverilog -g2012 -s tb_DDS -o tb/synth/tb_DDS.vvp rtl/synth/DDS.v tb/synth/tb_DDS.v
vvp tb/synth/tb_DDS.vvp
```

每次仿真先看错误计数/退出结果，再看波形；不以波形文件生成认定测试成功。只截取关键窗口，避免每次保存很大的VCD。

## 10/10：看懂现有 DDS 和一次采样

**学什么：** 非阻塞赋值中，同一个时钟沿读到旧寄存器值；时钟与时钟使能的区别。

**具体做：**
1. 打开 rtl/synth/DDS.v，逐行标注 phase、sample、sample_ce、STEP_440 各是什么。
2. 用纸画时钟0～8拍，使能只在第2、6拍为1，填写每拍phase值；先用步长3方便手算。
3. 运行现有tb_DDS，找到复位、相位更新、sample计算和频率测量的代码。
4. 对照波形确认sample使用更新前phase；想清楚这会改变起始相位，但不会改变稳定频率。
5. 按接口表写下核心输入输出、八键打包和默认零状态，不先给内部信号分配引脚。

**验收/交接：** 无sample_ce时phase不变，复位phase/sample为零；能用自己的话解释为什么不用50MHz代入音频频率公式。交A一张逐周期表，与B确认键编号。

## 10/11：把固定音高改为频率输入

**学什么：** phase_step=round(f×2^32/Fs)，相位回绕；改变频率字与改变采样率的区别。

**具体做：**
1. 保留原实现作为参考，不覆盖参考实验。DDS频率字从常量改成32位输入，内部累加使用该输入。
2. Fs固定48,828.125Hz，先用440Hz步长38702809与880Hz步长77405619。
3. testbench分三段：440、880、回到440，保持相位不因变调清零。
4. 测试无使能保持、接近最大相位的回绕、复位、连续采样；预期值由数学参考模型给出。
5. 把端口变化写给A；暂不加入按钮和音符选择。

**验收/交接：** 更新频率后周期约减半；实际测频误差与仿真时间窗相符，不要求短窗口测量恰好整数440。交DDS、tb和频率字计算方法，A可以用固定step连接。

## 10/12：相位变成正弦采样

**学什么：** 1024=2^10；phase[31:22]是地址；16位补码与同步ROM延迟。

**具体做：**
1. 阅读已有gen_sine_table.py与wave_rom_example.v，理解参考模块，不把示例文件名直接当正式top。
2. 核对波表1024行、每行4位十六进制；当前峰值8000，地址0/256/512/768应为0/8000/0/−8000。
3. 把相位接ROM地址，独立测试上述四个地址和边界1023→0。
4. 列出“请求沿→相位/地址→ROM结果→有效脉冲”的表，与A明确使用旧相位的行为。
5. 将正弦值接替方波，保存表、脚本、运行目录和初始化路径。

**验收/交接：** 有正负半周，无文件读入错误或X；输出频率随step变，地址与结果正确；A能复现仿真并将ROM/表加入工程。

## 10/13：做最简单的一路开关和增益

**学什么：** gate是保持状态；声音有符号、力度无符号；乘积位宽与缩放。

**具体做：**
1. 先用gate=1输出正弦、gate=0输出零，暂未加入ADSR，松开立即静音属于本阶段行为。
2. 选择通道0：gain=key_gain[15:0]，其他通道忽略但接口仍为八键。
3. 测0、32768、65535增益；用正负样本检查两半周都正确缩放。
4. 不把16位无符号gain直接解释成signed；先扩为17位非负signed值，16×17乘积保留33位，再缩放。
5. B未交真实输入时用固定满增益；真实模式复位仍为静音。

**验收/交接：** 零增益零输出、半增益约一半、满增益接近原值，负数不变成大正数。交A单声部接口与latency，交B一个可用的假控制例子。

## 10/14：真实一键闭环排错

**具体做：** 和A/B依次看原始ADC、gate/gain、核心采样/valid、I2S解码、喇叭，不同时修改全部链路。保持音高只改变压力；A仍用真实核心，不能用固定音源替代验收。

**验收/交接：** 静止无声、按下发声、压力改响度、松开停止。记录提交号、输入范围和现象；若卡住，交最小可复现仿真或参数，不只说“声音不对”。

## 10/15：单独实现 ADSR

**学什么：** 状态机五状态；Sustain是保持幅度，其他三个时间阶段按采样数变化。

**具体做：**
1. 先画Idle→Attack→Decay→Sustain→Release→Idle状态图，标注gate触发与端点条件。
2. 只仿真包络，暂不乘声音；按2/60/100ms计算约98/2930/4883个采样的目标。
3. Sustain≈65%，复位包络0；每sample_ce更新，其他拍保持。
4. 到峰值、保持值、零时限幅，避免相减下溢；小步长使用足够内部精度，不可变成0。

**验收/交接：** 包络曲线按设定方向变化，阶段时长与量化规则一致，长按维持Sustain。交A曲线及参数，不把状态机写完算全部通过。

## 10/16：ADSR 边界与单声部封装

**具体做：**
1. 按住进入Attack后提前松开，从当前包络Release；不得先跳到峰值或Sustain。
2. Release中重按，从当前包络重新Attack；测试快速重复、非常短按和长按。
3. 把DDS/ROM/ADSR/乘法封成voice，逐级标记数据对应哪次采样，延迟后的包络与ROM结果一起用。
4. 保存最近按住力度；松开控制帧gain=0时用保存值收尾，直到包络0。
5. testbench同一时刻给gate下降和gain归零，专门验证不截断Release。

**验收/交接：** 单voice完整按放、收尾、重按正确，data/valid固定延迟。交A可接模块、波表依赖、复位值和时序图。

## 10/17：四个独立声部和混音

**学什么：** 实例化复制模块不等于共享状态；符号扩展在求和前做。

**具体做：** 四份voice使用各自step/gate/gain；同一请求启动，全部结果属于同组才混音。统一使用为最终八声部预留的19位求和与固定除以八，四键阶段声音较小可调外部监听，不临时改成按键数归一化。

**验收/交接：** 四路同时保持；只松第二路，其他phase/env继续；极值/抵消不回绕。交A四键core和B通道对应表。

## 10/18：四键实物验收

**具体做：** 与A/B按单键、两键、四键、松第二键、改变单键压力的顺序演示。若单键压力影响全部响度，检查是否错误地用全局pressure_gain；若全部一起释放，检查共享包络。

**验收/交接：** 四个真实键分别控制四路，ADSR/力度独立；保存版本与已知问题。未过不开始大功能。

## 10/19：扩成八份 voice

**具体做：** 复制或generate八路，每路独立寄存器；扩音符表到C4…C5；核对第7路gain[127:112]。先假控制依次启用CH0…7，再同时启用；检查读取结构可给八路不同地址取数，不能认为单端口ROM能同拍读八地址。

**验收/交接：** 第5～8键也有独立状态，所有声部结果同一采样；交A依赖文件和资源变化，B核对八键映射。

## 10/20：八路极值与数据边界

**具体做：** 向混音测试输入八路32767、八路−32768、四正四负、全零与不同增益。用宽位数学模型算预期，检查扩展、右移、最终截位/限幅。测试controls_valid与sample_ce同沿，当前采样用旧帧、下次用新帧。

**验收/交接：** 求和无位宽丢失，固定比例，无混合新旧通道；交A极值结果及准确计算周期L。

## 10/21：八键闭环修复

**具体做：** 八键同按，逐个松开，单键改变力度；核对CH4…7不能映射错声部。失败分别定位核心、输入、发送，不整套重写。与A确认L≤128周期目标，正常无缺帧。

**验收/交接：** 八键八声部通过，代码/码流/接线记录同一版；用最小仿真保留已修问题的复现方法。

## 10/22：第二音色、八度和事件

**具体做：** 用相同峰值目标生成第二周期表0.75sinθ+0.25sin2θ；保证有符号与初始化完整。同一音高/相近响度比较。根据按钮循环修改音色/音区，参数在采样边界应用，step改变不清相位。事件在50MHz每拍接收，测试两次连续事件和多个位同时有效，不能被pending位合并。

**验收/交接：** 正弦和第二预设可听辨；连续声音实时升/降八度；事件不丢。交A/B状态规则和新波表。

## 10/23：四频率测试模式

**具体做：** 建立可重复纯正弦测试：固定四个非整数倍频率，例如440/554.37/659.25/830.61Hz，固定接近的增益。测试top把4位test_mask放入gate[3:0]，其余gate为零，配合固定力度与controls_valid形成假控制帧；核心测试模式用该帧的gate逐路开关，不新增正式核心端口。独立测试top使用假控制，演奏top使用B的真实控制，避免两种来源互相覆盖。测试默认四路开，A依次改mask录制谱峰；频率表按实际Fs生成。

**验收/交接：** 关闭一路只消失对应频点，避免用440/880/1320/1760把谐波与声部混淆。交A频率、mask、幅度与操作法；返回演奏使用最新真实控制帧。

## 10/24：配合真实延迟测量

**具体做：** 交A真实模式的L、ADSR、频率、幅度；不要为了好结果临时绕过输入/包络。发现起音过慢或控制滞后，区分ADC稳定/平滑、包络、缓冲及DAC，修改后完整重测。

**验收/交接：** 算法推算和实际波形分别表述，测量未通过写问题，未实测不宣称≤10ms。

## 10/25：核心回归与冻结

**具体做：** 一次运行DDS、ROM、ADSR、voice、混音、事件和端到端仿真；按早期验收场景复查。与A做30分钟连续演奏/测试、复位/上电；记录声音异常和缺帧，不增加混响等大功能。

**验收/交接：** 交冻结核心清单、全部依赖、测试方法和剩余问题；A用此版本出最终工程。

## 10/26：写 DDS、波表和定点章节

**具体做：** 用自己的代码解释phase_step公式、采样使能、1024表地址、补码和乘法缩放；画数据路径，标实际位宽。贴实际仿真窗口与参数，不堆教材定义。

**验收/交接：** A能从章节找到公式与代码对应位置；step按48,828.125Hz，波表实际峰值一致。

## 10/27：写 ADSR、混音、音色和参数章节

**具体做：** 说明五状态、当前值Release、冻结力度、重触发、固定除八；比较两音色同音高波形/频谱；附事件接收和参数应用时序。解释任何量化误差及已知限制。

**验收/交接：** 交A完整核心初稿和图表源文件；报告与冻结RTL一致。

## 10/28：工程重建依赖复核

**具体做：** 列出核心每个源码、表、脚本和路径；从干净的交付副本检查初始化文件存在。A另一电脑重建时协助ROM路径、位宽和综合问题，不修改原始参考实验。

**验收/交接：** 新电脑不依赖你的临时目录；A的重建步骤含必要表，不能只给.v漏.hex。

## 10/29：技术结论复核

**具体做：** 对报告中的“八声部、独立力度、并行、延迟、资源、两音色”逐项找证据；删掉未验证结论。和A核对测量版本、代码参数、码流，B核对每键力度接口。

**验收/交接：** 技术结论、证据、实际实现对应；列出仍待测项。

## 10/30：准备核心演示

**具体做：** 给A一份拍摄顺序：实时生成说明、八键和弦、只松一路、单键压力、音色/变调、四频点。准备简短解释，不用电脑预录音代替实物发声。

**验收/交接：** 每个演示动作对应指标和版本；A/B能按清单拍摄。

## 10/31：答辩自测

**具体做：** 不看代码回答：为何频率字控制音高？为啥每采样更新？声部独立状态在哪里？为啥19位求和？松开为何不被零增益截断？valid怎么对齐？讲不清的地方回到自己的实现核对。

**验收/交接：** 三人互问，记录问题并修正文档；不临时编造解释。

## 11/1：最终演练与核心版本确认

**具体做：** 按现场操作完整演一次，检查默认静音、模式、音区与重上电。记录最终提交号、参数、core依赖和限制，与A/B共同确认。

**验收/交接：** 演示过程无需现场改源码，材料和实物一致。

## 11/2：提交前技术审核

**具体做：** 检查报告图表、公式、音色名称、延迟表述；核对源码包内必要文件。只修确定错误，涉及功能修复必须通知A重建、复测、换码流。

**验收/交接：** 交A签核清单，不把旧码流和新源码混包。

## 11/3：最终确认

**具体做：** 与A逐项对提交文件、版本、证据；查看上传后文件能否打开和下载；保存技术确认记录。若改动发生，确认完整重新验证。

**验收/交接：** 正式提交内容与你复核的版本一致，必要限制已说明。

## 11/4：缓冲与修正

**具体做：** 仅处理平台、文件完整性、已定位缺陷等必要修正；支持答辩和演示。不在截止当天重构核心或增加效果器。

**验收/交接：** 最终确认和备份齐全，未通过项如实记录。

## 今日卡住时怎么办

频率不对先看Fs/step/sample_ce；只有正半周看signed与乘法；几路一起释放看是否共享状态；松手骤停看冻结力度；只有硬件无声先把输入换固定增益交A排输出。交问题时附输入、预期、实际、版本和波形窗口，让队友可以复现。
