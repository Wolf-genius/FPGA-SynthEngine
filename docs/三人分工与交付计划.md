# 选题二：三人分工与交付计划（第三版：队长主攻合成核心）

更新日期：2026-10-07。板卡：Tang Mega 60K NEO。截止日期按队长提供的信息为 11 月 4 日，提交格式和具体时刻以正式平台为准。

本版替代前两版，按队长明确提出的“队长负责核心任务，另外两人分摊其他任务”安排：队长承担完整实时合成引擎；A 承担音频输出、工程集成和测试；B 承担演奏输入、模拟采集和机械结构。A/B 都有自己需要实现、验证的技术模块，不只是写报告或采购。

已确认点灯和单音发声成功；当前从空工程手建 PMOD 点灯练习尚未收到完成确认。其他完成情况以实际演示为准。

## 一、整体分工

| 成员 | 主责 | 交付 |
|---|---|---|
| 队长 | 实时声音合成核心、算法方案、核心接口、功能取舍 | DDS、波形、ADSR、voice、四声部管理、混音/力度控制、参数与测试模式的 synth_core |
| A | 音频输出、Gowin 工程、系统集成、测量和验证 | audio_tx、采样时序、final top、CST/SDC、串行接收测试、频谱/延迟证据、可重建工程 |
| B | 演奏动作采集、输入参数、接线和结构 | 四路琴键输入、ADC 驱动、压力映射/平滑、功能按钮、接线表、可演奏结构 |

数据流：B 将动作变成控制数字 → 队长在 FPGA 内实时计算声音 → A 把采样数字送到 DAC 和音箱。A 负责维护总工程，队长决定核心接口和整体技术方案，三人共同进行整机验收。

第一版建议四路光电琴键 + 独立压力垫，四键固定对应四个声部。先不做复杂动态声部分配。硬件可按最终采购调整，但输入接口保持稳定。

基础验收覆盖：至少两个独立可控演奏维度、至少四个独立声部、实时变调、ADSR、混音、HDL 实时生成音频、控制到模拟输出总延迟不超过 10ms，以及赛题要求的 I2S 到 DAC 输出。基础闭环后安排第二音色等拓展。

## 二、队长：合成引擎的全部核心开发

### 1. DDS 与频率控制

- 编写独立相位累加器：每次音频采样向前走一定相位，从相位得到波形位置。
- 用 32 位 phase_step 控制频率，根据 A 确认的实际采样率计算 round(频率 × 2^32 / 采样率)。
- 先验证 440Hz 与 880Hz，再整理初始四个音符和运行时变调参数。
- 支持持续发声期间修改指定声部频率；首版保持相位连续。
- 写独立仿真，验证周期、参数更新和复位。

### 2. 波形和音色

- 先用方波验证，再用数学公式生成单周期正弦波表。
- 明确波表点数、位宽、正负号、幅度和相位到地址的映射。
- 使用同步 ROM 时说明读取延迟，把初始化文件和生成脚本纳入交付。
- 基础稳定后加入第二种有区别的波形/音色，比较时使用同音高和接近响度。
- 所有声音逐样本实时生成，不使用整段录音触发发声。

### 3. ADSR 包络

- 实现空闲、起音、衰减、保持、释放状态。
- 包络每个采样更新，避免误按主时钟频率运行。
- Sustain 是保持音量；Release 从松开时当前音量开始下降。
- 对峰值和零值限幅，防止数值上溢/下溢。
- 验证起音中松开、释放中重按、快速重复和长按。

### 4. 单声部 voice 与四声部 voice_bank

- 单声部包含独立相位、频率、波形和包络，输出有符号采样。
- 波形乘包络时处理正确符号、乘法位宽和缩放。
- 实例化四份 voice，各有独立状态；四键固定对应四路。
- 四路允许同时发声，单独开始、释放和变调。
- 验证四键同时按住、只松开第二键，其他三路继续。
- 明确一次采样请求后各路何时有效，不能混合同一组里的新旧采样。

### 5. 混音与力度控制

- 四路 16 位有符号采样求和，至少使用 18 位，并在相加前符号扩展。
- 首版固定缩放，留足四声部峰值余量，不按当前键数突然改变比例。
- 将 B 的 pressure_gain 应用于混音，控制响度，不改振荡器频率。
- 无符号增益与有符号音频相乘时显式处理符号和位宽。
- 最终输出限制到目标范围，避免回绕。
- 仿真四路最大/最小值、同相峰值、正负抵消及不同增益。

### 6. 参数管理、测试模式和 synth_core

- 接收 B 的功能按键事件，实现模式切换、音色选择、指定声部变调。
- 控制参数按约定的采样边界整体更新。
- 演奏模式使用实际 gate 和压力；测试模式能开启四个不同频率纯正弦声部，便于验证谱峰。
- 封装 synth_core，外部只需输入控制和采样请求，输出 mixed_sample、mixed_valid。
- 报告核心的实际运算延迟、资源和算法，A 协助测量与复核。

队长交付：dds、wave_rom、adsr、voice、voice_bank、mixer、synth_core 及参数逻辑（可按规模合并文件），仿真/波表文件、模块接口时序和合成原理章节。模块数量不是考核依据，功能与验证完整才是。

队长协调任务限制为接口决策、核心评审、进度取舍和最终材料确认。采购接线、输出驱动、总工程维护、测量资料和各人报告初稿分给 A/B，保护核心开发时间。

## 三、A：输出链路、工程集成和验证

### 1. 独立音频发送器

- 复现现有成功的单音工程，理解发送时钟、声道选择、串行位顺序和采样装载。
- 将发送部分拆成 audio_tx，输入声音数字，不在其中生成音调。
- 用固定数值先验证，检查左右声道、正负数、零值和极值。
- 静音时连续发送零，音频时钟不中断。
- 实现串行接收 testbench，将输出位拼回采样，验证内容和时序。

### 2. 最终 I2S 路线与采样时序

- NEO 板载 PT8211-S 为 LSB-justified/Japanese 格式，网络名 I2S_* 不能证明标准 I2S。
- 按赛题要求落实标准 I2S 输出及匹配 DAC，核对实际模块供电、逻辑电平、格式和 MCLK 要求。
- 当前单音练习采样率为 48,828.125Hz，不能称为精确 48kHz；改变输出时序后重新计算并通知队长。
- 给合成核心提供 sample_ce，明确“请求哪一帧”“何时必须完成”“在哪个时刻发送”。
- 为核心返回采样设置缓冲，避免在同一时钟沿更新寄存器后误认为已拿到新数据。
- 未准备好时可使用预定静音策略排错，但正常运行必须没有缺帧，并记录实际流水线延迟。

### 3. Gowin 工程与总 top

- 自己掌握新建、添加文件、顶层设置、综合、布局布线、生成码流和下载。
- 维护 final top，将 B 的输入、队长的核心和 audio_tx 连接起来。
- 维护 CST、SDC、器件和双用途引脚设置，核对 Bank 电压及接口复用。
- 先一条链路联通，再接四声部、压力和功能按钮。
- 保留能运行的版本和源码到 .fs 的对应记录，避免误下旧文件。
- 检查综合/布局日志、时序和资源；不能以“综合成功”代替时序通过。

### 4. 测量、系统测试和材料

- 制作验证清单和测试脚本，发现问题时保存可重复的输入、预期和实际结果。
- 运行队长提供的四频率测试模式，采集频谱，确认谱峰随对应声部开关变化；不能把一个音的谐波误认为独立声部。
- 与 B 测实际控制起点到模拟音频输出的总延迟，记录仪器、触发、幅度判据和重复结果；内部 valid 只作辅助。
- 组织四音保持、快速按放、压力变化、变调、复位和重新上电验证。
- 负责另一台电脑上的工程重建、演示视频拍摄剪辑和输出/整机测试报告章节。
- 统合三人报告初稿，队长复核技术结论；不替 B 写硬件原理，也不替队长写全部算法。

A 交付：audio_tx、采样时序、final top、CST/SDC、完整 Gowin 工程、接收仿真、整机测试证据、视频和报告章节。合成错误由队长修复，A 负责复现和定位；输出/集成错误由 A 修复。

## 四、B：输入采集、硬件与演奏结构

### 1. 琴键输入

- 先练一路按钮，区分 held 按住状态与 pressed/released 事件。
- 核对光电模块供电、电平与有效方向，异步输入先同步到主时钟域。
- 做必要稳定判定，实测挡片在槽口晃动的误触发；不盲目套用过长机械消抖。
- 从一路扩到四路，输出 gate[3:0]，可同时按多个键。
- 测长保持、快速重复、环境变化及四路独立性。

### 2. 压力电路和 ADC

- 根据实际压力片搭分压，核对允许电压与尾部引线，避免直接误焊柔性部分。
- 按实际 ADC 手册实现 SPI 帧、采样、片选、位序和有效信号。
- 用可控电压先验证读数，再接压力片，记录轻重按和稳定压力数据。
- 做校准、限幅和轻度平滑；记录更新率和滤波响应。
- 输出 16 位无符号 pressure_gain，不让队长在合成代码里处理原始电气读数。

### 3. 功能键、结构和采购落实

- 做大按钮同步/消抖，提供模式/变调事件，事件不会重复或丢失。
- 整理传感器及配件规格、采购数量和到货检查；A 核对音频 DAC/音箱规格。
- 制作四个可按、可回位的琴键与挡片，固定独立压力垫。
- 做完整接线表、线缆标号和固定结构。与 A 核对扩展 GPIO 电压和复用，不接错 1.5V/3.3V 引脚。
- 验证保持同一和弦时压力可独立改变，压力固定时琴键也可独立操作。
- 交互/硬件报告、结构照片与现场操作说明由 B 主写。

B 交付：key_scan、adc_spi、pressure_map、功能键/输入处理及仿真，可靠演奏结构、接线表、输入测试和报告章节。只有一块板时提前与 A 排好硬件使用时间。

## 五、先固定接口，三人才能同时推进

| 信号 | 提供者 → 接收者 | 含义 |
|---|---|---|
| clk、rst_n | A 的总 top → 全部模块 | 同一主时钟域、统一复位与释放 |
| sample_ce | A → 队长 synth_core | 一主时钟周期使能，每组音频采样一次，实际采样率固定并记录 |
| gate[3:0] | B → 队长 | 1=按住、0=松开，已同步，允许多位同时为1 |
| pressure_gain[15:0] | B → 队长 | 无符号；0=零增益、65535≈单位增益；无压力和复位初值一致约定 |
| button_events | B → 队长 | 模式、音色和变调事件，有明确接受/保持机制 |
| mixed_sample、mixed_valid | 队长 → A | 16位有符号混音及有效脉冲，固定已知延迟，在发送期限前完成 |

每个模块附：端口与符号、更新条件、输出有效时刻、复位值、独立测试方法。多位参数整体交接，短事件保留到被接收，不用逐位同步代替一致性，也不假定短脉冲一定遇到采样使能。

先采用简单的固定流水线安排：采样请求生成下一帧数据，运算完成进入输出缓冲，下一帧装载发送，首帧为零。A 制作时序表，队长反馈核心延迟，两人确认总计算时间小于交付窗口，B 反馈采集/滤波延迟。

独立开发方法：队长用假 gate、固定压力做仿真；A 用固定采样或测试波形验证发送；B 用 LED/读数观察输入。不用等核心写完才开始输出与输入任务。
